# Comment on #38522 — Subagent barrier primitive (spawn N, await all)

**Target:** https://github.com/openclaw/openclaw/issues/38522
**Tone:** technical, acknowledging, offer to collaborate
**Why:** direct overlap with Phase 1 of Octo's competitive grip spawn

---

Hi @softengineware — just read this proposal and it lines up almost
exactly with a primitive the Octopus Orchestrator work (#64392 /
#64435) uses internally as the first phase of any competitive grip
spawn. Sharing in case it's useful context.

Your core primitive:

```
sessions_spawn_barrier({
  tasks: [...],
  awaitMode: "all" | "any" | {minComplete: N},
  timeout,
  timeoutBehavior
}) => { status, results, pendingTasks }
```

This is exactly the shape Octo uses to run `N work arms in parallel`
as Phase 1 of a `competitive`, `competitive_single_judge`, `council`,
or `consensus` mission. The "fragile coordination logic" and
"token-inefficient polling" you flagged are real — I hit both before
settling on the current design.

**How Octo handles the same underlying problem:**

- **Atomic cohort launch** → arms are spawned together via a single
  `octo.mission.create` call; each arm gets an idempotency key so
  replays don't double-spawn
- **Timeout with partial completion** → each grip has a `timeout_s`;
  when the deadline hits, the mission's `awaitMode` equivalent is
  encoded in the execution strategy (e.g., `council` waits for all,
  `competitive` waits for all but tolerates judge-phase failures,
  etc.)
- **Durable state** → mission / grip / arm rows live in a SQLite
  registry with versioned CAS updates. Restart-safe.
- **Buffered + streamed completion** → arms write to sentinel files
  for completion signals; the append-only event log captures every
  state transition as a stream consumers can tail.
- **Result stitching** → each grip's `result_ref` points at the
  completed arm's output file at
  `~/.openclaw/octo/artifacts/<mission>/<grip>-<arm>.txt`. The next
  phase's arm reads dependent results via prompt substitution.

**Where your proposal and Octo differ:**

Your barrier is **single-cohort**: spawn N, wait, return. Octo adds
**DAG edges** so cohorts cascade — grip A completing automatically
triggers grip B's arm (with A's output as B's input) without a
parent polling for completions. That's the pattern that makes `work
→ judge → verdict` work end-to-end.

In other words: your barrier primitive is **Phase 1 of an Octo
mission graph**, and Octo adds Phases 2, 3, ... via dependency edges.
Both are valid; single-cohort fan-out is simpler and probably
sufficient for a large class of use cases.

**Concrete places in the fork:**

- `src/octo/head/strategies/competitive.ts` — expands a single grip
  into a 2N+1-grip DAG (N work + N judge + 1 verdict)
- `src/octo/head/strategies/council.ts` — N work + 1 synthesizer
- `src/octo/node-agent/agent.ts` — phase cascade logic; when a grip
  completes, auto-spawn any dependent grips whose dependencies are
  all satisfied
- `src/octo/head/scheduler.ts` — the grip assignment loop that picks
  next-ready grips matching available arm capabilities

Link to the fork: [`mmartoccia/openclaw@octopus-orchestrator-clean`](https://github.com/mmartoccia/openclaw/tree/octopus-orchestrator-clean)

**Where I'd love your input:**

1. **Should Octo expose a `sessions_spawn_barrier`-shaped convenience
   verb** so callers who don't need the DAG can get just the fan-out/
   await behavior without buying into mission/grip/arm? The code is
   already there — it'd be a thin wrapper exposing a single grip
   whose execution strategy is `parallel_cohort`. Low-cost, high-
   reuse.
2. **Or should your barrier primitive land independently** and Octo
   reuse it as its Phase-1 implementation? The layering is cleaner
   if you own the primitive and Octo composes it, rather than both
   proposing parallel implementations.

Strongly lean toward option 2. Happy to iterate on the API together
if you're still interested in landing your proposal — the gap
between "what Octo uses internally" and "what your barrier proposal
describes" is small enough that we should converge on one shape
rather than diverge.
